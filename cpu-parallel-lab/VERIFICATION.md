# 本机验证记录

日期：2026-10-28（Asia/Shanghai）。

## 环境与构建

- CPU：Intel Core i5-9300H，4 个物理核心 / 8 个逻辑处理器。
- Windows 10，MSVC 19.51，Visual Studio 2026，Windows SDK 10.0.26100.0，x64。
- Release 和 Debug 均成功编译；当前构建无编译警告。
- 两个配置的 CTest 均为 2/2 通过：`concurrency_contracts`、`gui_contracts`。
- 本机生成的 VS 工程：`build/CpuParallelLab.slnx`；可执行文件在 `build/Release/` 和 `build/Debug/`。

## 正确性

`concurrency_contracts` 覆盖：

- 73×41 的非整除尺寸，tile 4/16/64/128，7 个工作线程，三种调度模式。
- 每个像素恰好被一个图块覆盖，无缺漏、无重叠；工作线程数量可以多于图块。
- 每种调度和图块大小都与串行参考完整像素数组相等。
- 每线程完成数之和等于总图块数；开始、结束时间和 owner 范围正确。
- 计算中持续读取进度和已发布图块的图像快照。
- 运行中二次 Start 被拒绝；取消、取消后复用、运行中析构和无效参数。

`gui_contracts` 在应用进程内部调用真实的 Start / Tick / Paint 流程，检查：

- 一键对照从串行正确切换至并行，两次结果一致。
- 运行期间锁定参数，完成时恢复；完整结果允许导出。
- 取消会终止整个两阶段对照，取消结果禁用导出；之后能重新运行。
- 下拉框保留选中值；同一套原生绘制代码生成离屏界面预览。

命令行另外验证了 `--samples 0` 和 `--samples 12abc` 均返回非零，未默默接受错误参数。

这些测试未使用 ThreadSanitizer，不等同于形式化证明。线程同步还进行了源码检查，发布边界在 README 中说明。

## 正式性能测量

```powershell
.\build\Release\cpu_benchmark.exe --width 640 --height 360 --samples 256 --repeats 3 --output out\benchmark-long
```

固定 640×360、每像素 256 次采样、反射上限 5、tile 32；各池用完整负载预热，正式运行每组 3 次，每轮交替配置顺序。中位数如下：

| 模式 | 工作线程 | 中位时间 ms | 最小–最大 ms | 相对串行加速 |
|---|---:|---:|---:|---:|
| 串行 | 1 | 8414.30 | 8368.35–8417.32 | 1.00× |
| 静态 | 1 | 8415.86 | 8384.79–8417.07 | 1.00× |
| 动态 | 1 | 8410.96 | 8392.16–8418.56 | 1.00× |
| 静态 | 2 | 5052.92 | 4994.67–5058.30 | 1.67× |
| 动态 | 2 | 4328.85 | 4295.19–4678.28 | 1.94× |
| 静态 | 4 | 3275.81 | 3222.77–3288.53 | 2.57× |
| 动态 | 4 | 2386.04 | 2324.38–2422.44 | 3.53× |
| 静态 | 8 | 2033.03 | 2021.40–2069.94 | 4.14× |
| 动态 | 8 | 1513.86 | 1502.82–1555.89 | 5.56× |

动态 1/2/4/8 线程的平均 CPU 并行度中位数分别约 1.00 / 1.99 / 3.98 / 7.88。8 线程的 CPU 总工作时间高于串行，同时墙钟时间显著下降；加速比 5.56 不等于 CPU 并行度 7.88。SMT、频率和额外调度等因素可能影响这两个指标，当前实验没有单独隔离它们。

同为 8 线程，动态调度相对静态的墙钟时间减少约 25.5%。这说明在本场景里，负载分配影响完成时间；不代表其他场景都应该使用这一策略。

27 次正式输出逐像素一致，checksum 均为 `13096196304500204266`。额外解析验证了 9 份完整 JSON 和 2160 个 trace 事件，检查完成数、每线程图块总数和非负区间。

原始证据：

- [每轮样本](out/benchmark-long/samples.csv)
- [统计汇总](out/benchmark-long/summary.csv)
- [8 线程动态最后一轮](out/benchmark-long/dynamic-8.json)
- [8 线程动态时间线](out/benchmark-long/dynamic-8.trace.json)
- [8 线程静态时间线](out/benchmark-long/static-8.trace.json)
- [最终图像](out/benchmark-long/render.bmp)

另保留 480×270、64 采样的短负载结果于 `out/benchmark/`。短负载的一轮 8 线程 CPU 并行度出现 8.25，源于约 0.21 秒任务上有限的系统记账粒度；因此没有把短时原始值包装成精确利用率，并补做上述较长负载测量。

三轮结果只描述这台机器这次运行，不是普适性能保证。没有固定 CPU 亲和性、关闭 SMT、锁定频率或控制所有后台任务；2 线程动态的一轮波动可直接在原始数据中看到。

## 界面验证的边界

应用已成功启动并报告窗口正常响应。Computer Use 的窗口激活/截图接口在刷新目标后仍出现 `failed to activate captured window` / `FrameArrived timed out`，因此没有声称真实鼠标点击的端到端验证已完成。

真实桌面鼠标交互、不同 DPI / 多显示器和超过 8 线程的时间线翻页尚未完成人工检查。中文离线教学页已提供，未做浏览器端到端测试。
